Privacy Policy

Last updated: 12 September 2026

CodeExplainedBadly ("the app") is a private, first-party automation tool operated by an individual ("the operator") to publish videos to the operator's own YouTube channels. This policy explains what data the app accesses and how it is used.

Data the app accesses

With the operator's explicit Google OAuth consent, the app requests the YouTube Data API scopes https://www.googleapis.com/auth/youtube.upload and https://www.googleapis.com/auth/youtube. These are used only to:

  • upload videos and YouTube Shorts to the operator's own channels;
  • set the title, description, tags, and privacy status of those uploads.

The app does not read, collect, or process any other person's Google or YouTube data. It is used solely by the operator on the operator's own account.

How data is stored

The OAuth refresh token issued by Google is stored locally in the operator's own environment (a local .env file on the operator's machine) and is used only to obtain short-lived access tokens to call the YouTube Data API. Tokens are never transmitted to any third party and are never shared, sold, or used for advertising.

Data sharing

The app does not share, sell, rent, or transfer any Google user data to third parties. No human reads the data; it is used only programmatically to perform the uploads described above.

Google API Services User Data Policy (Limited Use)

The app's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Data obtained through Google APIs is used only to provide and improve the single, user-facing feature described here (uploading the operator's own videos) and is not used for advertising, sold, or transferred except as required for that feature, to comply with law, or as part of an approved merger.

Revoking access

The operator can revoke the app's access at any time at Google Account → Third-party access. Revoking invalidates the stored token immediately.

Data retention & deletion

The only stored artifact is the local refresh token, which the operator can delete at any time by removing it from the local .env file and/or revoking access as above. No server-side copies are kept.
